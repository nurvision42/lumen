# 视频拆解

用户明确要求拆解、拉片、按镜头分析一条成片时，再运行 `lumen breakdown`。不要因为对话里出现了视频就自动拆解。

省略 `--prompt` 时，用已绑定的拆解提示词；没有绑定就用内置拉片表。不要把内置拉片表再贴进命令。绑定：`lumen breakdown prompt set --text <中文>` 或 `--file <path>`，正文会复制进配置，源文件之后挪走也不受影响。不加 `--project` 写到用户目录 `~/.config/lumen`（`providers.json` 的 `breakdown.prompt`）；`--project` 或 `--project <dir>` 只写该项目的 `lumen.config.json`。`lumen breakdown prompt show` 打印生效提示词和来源（`flag`、`project`、`global`、`built-in`）。`lumen breakdown prompt clear` 清除全局，`lumen breakdown prompt clear --project` 清除项目。单次覆盖用 `--prompt` 或 `--prompt-file`。优先级是 `--prompt`、`--prompt-file`、项目绑定或项目配置、全局绑定、内置。

```text
lumen breakdown --video <file>
```

默认 `--dry-run` 只记请求。用户明确要提交时才加 `--execute --detach`，再用 `lumen runs wait <id> --timeout 60` 取结果。不要前台一直等。如果输出 `running` 并提示 `lumen runs resume <id>`，任务还在服务端跑，用 `lumen runs resume <id> --execute --detach` 接着等同一个任务，不要重新拆解。

不发送 `scene`。默认模型 `doubao-seed-2-1-pro-260915`（画面分析）和 `doubao-seed-2-0-lite-260428`，`level` 为 `Quality`，需要音频。不要问用户改模型。`doubao-seed-2-1-lite-260915` 不能处理音频。`need_audio` 需要 `doubao-seed-2-0-lite-260428` 或 `doubao-seed-2-0-mini-260428`，并且请求里要有该模型的方舟推理接入点。只写 `prefer_models` 会失败，`status_code=11100`。接入点用可重复的 `--prefer-endpoint <ep-id>`，或环境变量 `LUMEN_MEDIAKIT_ENDPOINTS`（逗号分隔），或配置 `breakdown.preferEndpoints`。优先级是命令行、环境变量、配置。列表为空就不要发 `prefer_endpoints`。不要编造接入点 id；用户没有就先不传。

## 结果怎么展示

模型的回答可能是一张表。展示给用户时不要用 14 列宽表。每个镜头单独一节，字幕/台词放在这一节最上面，其余字段各占一行：

```text
镜头 3
字幕/台词：……
起止时间码：……
时长(秒)：……
概述：……
叙事作用：……
景别：……
画面元素：……
镜头运动：……
转场/剪辑：……
声音/音乐：……
情绪/节奏：……
视觉风格：……
备注/置信度：……
```

听不清或看不清的字段写「未识别」。不要并成宽表，不要省略镜头。
