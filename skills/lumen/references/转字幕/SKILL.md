# 转字幕

用户要字幕文稿、要核对口播、或成片最后一步要压字幕之前，读本文件。只跑 `lumen captions transcribe`。不要自己拼请求，不要自己调语音识别。

这一步只出字幕，不把字压进画面。压画面用加字幕，读 `skills/lumen/references/加字幕/SKILL.md`。

## 何时用

用户要识别、要校对字幕，或核对文字之后要压字幕。不要因为对话里出现了视频就自动转字幕。

校对前的识别一律加上 `--no-script`。项目里已经有镜头口播，或已经跑过语音合成、声音克隆，也要加上。漏掉这个旗标时，命令仍会自己找文案；对得上就会改写条目。那是命令现在的行为。校对从 `--no-script` 写出的识别文件开始。

## 命令

```text
lumen captions transcribe --video <file> --no-script
```

默认 `--dry-run`：只把将要提交的请求写进审计，不上传，不写字幕文件。用户明确要识别时加 `--execute`。`--mock` 用内置假传输，不写字幕文件。`--script` 和 `--no-script` 不能同时用。

`--video` 可以是项目里的文件，也可以是一条已有的远程地址。本地文件的片长用 ffprobe 读。结束时间超过片长的会被裁短，整段落在片长之外的会丢掉，避免字幕把成片拖出黑尾。远程地址没有本地片长时，用识别服务返回的时长。这次裁切发生在写出识别文件的时候。文件写出之后，校对不再改时间，也不再删条。

输出默认在 `refs/<运行编号>.captions.json`，旁边有一份同名 `.txt` 方便读。`--to` 改 JSON 的位置，文本跟在旁边。需要交换文件时再加 `--srt` 或 `--ass`。ASS 只是交换格式，圆角底不在这一步画。已有同名文件时命令拒绝覆盖。

JSON 里看这几项：

- `duration`：用来裁时间的片长，单位秒。
- `clamped`：`true` 表示写出识别文件时有条目被裁短或丢掉。
- `confirmed`：`--no-script` 写出的是 `false`。`true` 才能不带 `--confirm` 直接拿去加字幕。
- `script`：`--no-script` 时是 `null`。对照过文案时才有来源、相似度 `fit` 和有没有 `applied`。
- `cues`：每条 `start`、`end`、`text`。开了说话人时还有 `speaker`。
- `asrDuration`：服务返回的时长，和 `duration` 不一样时才会出现。

标准输出也会写片长、是否裁过、是否确认、文案和条数。

## 校对只改文字

识别命令写出的 JSON、旁边的 `.txt`，以及这次命令写出的 `.srt`、`.ass`，都是原文，保持不动。校正写到另一个文件，在 JSON 扩展名前面加上 `.proof`，例如 `refs/<运行编号>.captions.proof.json`。用了 `--to` 时，同样留着那份原文，校正写到旁边的新文件。用户后来同意改时间，也写到另一份，仍然不动原文。

校对只改每条的 `text`。条数、顺序、每条怎么切开、`start`、`end` 都保持识别文件里的值，数字也保持原样。不合并，不拆开，不插入，不删除，不改写时间。`speaker` 保持原样。不要把某条 `text` 改成空的，空文字在压制时会被跳过，条数就变了。

逗号、顿号或句号两边，在识别文件里已经是前后两条短句时，就按这两条原来的起止时间先后显示。标点只表示字怎么断，不能用来推断哪一半是什么时候说的。一条字幕里带着标点，仍然用这一条原来的 `start` 和 `end`。不要按字数把一段时间分给标点两边，也不要把按字数摊出来的时间说成精确时间。

某条的时间和听到的话对不上，或者看起来应该合并、拆开、补上、删掉一条时，先停手。把原来的条数、每条文字和起止时间告诉用户，并说明想怎么改。用户明确同意这一次改时间或重切之前，校正文件里的条数和时间保持原样。同意只覆盖用户点过的那几条，其余条目仍只改文字。

## 不带 `--no-script` 时命令仍会改写

下面是当前命令的行为，用来说明校对为什么必须先加 `--no-script`。不传这个旗标、又对上了文案时，写出的文件就不再是识别原文。找不到文案，或相似度不够时，条目可以仍是识别结果；校对还是先加 `--no-script`，免得这一步被文案改写。

不传 `--script`、也不传 `--no-script` 时，按这个顺序找文案：

1. 镜头表里非空的口播。时间用每条 `durationSec` 从 0 累加，空口播的镜头也占时长，后面的句子不会挤到前面。
2. 口播是空的，但这个镜头有一次成功的语音合成或声音克隆。用那次稿子，时间仍按镜头时长。
3. 没有镜头表，但有成功的合成或克隆。把稿子接成一整段，再按识别出的时间对齐。

`--script <file>` 改用你给的文件，不再自动找。纯文本走下一段的对齐，会改字，也可能插入或丢掉条目。带 `-->` 的字幕、带起止时间的 JSON、带口播列的镜头表，按文件里的条目重写：每条先用文案的起止时间；这段里有识别条目时，起止收紧到这些条目落在文案时间里的范围。条数跟着文案，不跟着识别结果。

对照用的是去掉标点和空白后的重合比例。`fit` 达到 0.55 才把文案写进字幕并标成已确认。纯文本这一路会把错字换成文案，把漏掉的长句补进空隙，把文案里没有的字丢掉，条数也可能变。带时间的文案则按上一段重写条目和时间。低于 0.55 不改识别结果，`confirmed` 为 false，`applied` 为 false。识别是空的、但文案自带时间时，仍按文案的时间写出条目，但不自动确认。

对得上时，这条路径会改变条数、切分或时间。校对不要用它。对得上之后写出的文件不能当作识别原文。

## 绑定

模型 `asr-subtitles`，供应商只有 `mediakit`。每个模型一条绑定，不会借用拆解或增强的密钥。

```text
lumen providers set asr-subtitles --provider mediakit --api-key-env <你的变量名>
```

密钥放在这个环境变量里，不要写进命令、项目或对话。缺密钥就让 `--execute` 失败。`--language` 可传 `cmn-Hans-CN`、`eng-US`、`spa-ES`、`ind-ID`；不传则由服务自己判断。多人说话时加 `--speaker`。

## 确认之后

`--no-script` 的识别文件 `confirmed` 为 false。校对副本保持其余字段不动，`confirmed` 仍是 false，只改了 `text`。

要压画面时，`--subs` 指向校对副本，并加 `--confirm`。`--confirm` 只表示按这份文件里的条目压制。它不改条数，不改时间。文字还没核对完，或时间和切分还在等用户同意时，不要压。

不要把未改动的识别原文直接压进成片，除非用户明确要压原文。细则读 `skills/lumen/references/加字幕/SKILL.md`。
